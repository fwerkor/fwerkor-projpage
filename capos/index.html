CapOS

SYSTEM MODEL

系统组件和用户应用分开管理。

CapOS 自己的内核、驱动、网络、存储、WebDesktop 和 snapd 等系统组件继续由 CapOS / OpenWrt 包体系维护；用户应用直接来自官方 Snap Store。这样不需要再维护一套 CapOS 专用的第三方应用仓库。

WEBDESKTOP

浏览器端管理

WebDesktop 负责系统管理与应用入口。它通过 /run/snapd.socket 与 snapd 通信，可执行应用安装、更新和移除，并自动发现 Snap 暴露的 Web 服务。

02

APPLICATION MODEL

不维护平行应用生态

第三方应用不需要重新打包成 CapOS 专用格式。用户应用由 Snap 安装，CapOS 只维护系统层和应用运行所需的基础能力。

Snap StoresnapdWebDesktop
03

COMPATIBILITY

systemd-on-procd

CapOS 保持 procd 作为 PID 1，同时通过 systemd-on-procd 提供常见的 systemd 命令与 unit 边界，让更多面向 systemd 的软件可以进入现有服务模型。

04

ROOT FILESYSTEM

ArgosFS 路径

常规固件构建继续支持 ArgosFS 根文件系统路径；项目也提供独立的 OCI 系统镜像构建，用于需要标准容器镜像布局的场景。
